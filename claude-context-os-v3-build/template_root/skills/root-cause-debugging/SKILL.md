# Root Cause Debugging

Do not patch from the symptom alone. Reproduce or collect evidence, identify the failing boundary, compare expected vs actual state, form the smallest testable hypothesis, and change only after evidence supports a cause.

After a verified fix, capture a reusable FIX card only if the root cause is likely to recur. Record the symptom, root cause, evidence, exact fix pattern, applicability limits, and verification. Never generalize a project-specific workaround into a global rule without evidence.
