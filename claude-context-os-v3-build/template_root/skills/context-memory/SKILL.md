# Context Memory

Before retrieval, identify the active project and current task. Search the smallest relevant scope first: project, then domain, then global reusable knowledge. Do not load entire history.

Treat retrieved fixes as leads, not truth. Confirm current code, schema, and environment before reuse.

Promote knowledge only when verified and likely to matter again. Store one focused concept per knowledge card with: type, project/domain, problem or fact, evidence, applicability constraints, verification, related projects, and date. Never store secrets, raw credentials, auth tokens, private keys, or sensitive query results.

Promotion levels are temporary, session, project, reusable, and global. Default to the narrowest sufficient scope.
